## Repo layout

- `www/index.html`: the web app (a copy of the project's `Amplify.html` plus Android-only
  additions, all guarded by `Capacitor.isNativePlatform()`). **Note:** the Android-only changes
  exist only here, not in the project's `Amplify.html`. If Mark updates `Amplify.html`, the
  Android additions must be carried over.
- `android/app/src/main/java/com/markcoleman/amplify/`
  - `MainActivity.java`: Capacitor activity.
  - `AmplifyPlayerPlugin.java`: Capacitor plugin "AmplifyPlayer", the page↔native bridge.
    Methods: `load/play/pause/stop/seek/setVolume/setRate/setSkip/setMetadata`, local-file cache
    (`cacheCheck/cacheWrite/cacheFinish`: library blobs copied from IndexedDB for native
    playback), `pickMusicFolder` (SAF tree picker, walks folder, returns content:// uris),
    `setCarCatalog`, `takeCarProgress`. Events: `state`, `progress`, `error`, `remote`.
    `onCarTookOver()` emits an external pause to the page when the car starts its own playback.
  - `PlaybackService.java`: **MediaLibraryService** hosting ExoPlayer + `MediaLibrarySession`.
    `LibraryCallback` = onGetLibraryRoot / onGetItem / onGetChildren / onSetMediaItems /
    onAddMediaItems, all delegating to `CarLibrary`. Saves car podcast progress every 10 s. Sets
    podcast speed on item transition. `onTaskRemoved` keeps car playback alive.
  - `SkipAwarePlayer.java`: ForwardingPlayer the session sees. Normally routes transport
    commands to the page (which owns the queue) and uses page-supplied metadata. **Car mode
    (`nativeMode`)** starts when the session calls `setMediaItem(s)` (only the car/controllers
    do; the plugin drives ExoPlayer directly). In car mode ExoPlayer's own queue and next/prev
    are used, and metadata comes from the MediaItem (live stations show the ICY song as artist).
    `exitNativeMode()` is called by the plugin's `load()`.
  - `CarLibrary.java`: the Android Auto browse tree, built from a **catalog JSON the page saves**
    (`files/car_catalog.json`). Node ids: `root`, `tab:home|library|stations|podcasts`,
    `home:*`, `lib:*`, `st:foryou|recent|top`, `fy:<id>`, `pod:latest|az|popular`, `cat:<id>`,
    `show:<collectionId>` (episodes fetched live from the iTunes lookup API, cached 30 min).
    A playable id is `<node>|<index>|<key>`; `queueFor(id)` rebuilds that list as an ExoPlayer
    queue starting at the tapped item (and resolves .pls/.m3u links). Uses raw MediaConstants
    extra strings (content style list, group titles for date headings, completion status).
  - `CarProgress.java`: `files/car_progress.json`, guid → position/duration/record for episodes
    played in the car. The page takes and merges it (`takeCarProgress`) on start and on resume.
  - `ArtProvider.java`: content provider `com.markcoleman.amplify.art`. Android Auto only loads
    artwork via content:// uris, so `ArtProvider.uriFor(httpUrl)` → `content://…art/<base64url>`,
    downloaded into the cache on first open.
- `AndroidManifest.xml`: service with MediaLibraryService/MediaSessionService/MediaBrowserService
  actions, `com.google.android.gms.car.application` meta-data → `res/xml/automotive_app_desc.xml`
  (`<uses name="media"/>`), exported ArtProvider. Tab icons `res/drawable/ic_car_*.xml`.
- `.github/workflows/build.yml`: npm ci → cap sync → `./gradlew assembleRelease` → build-output
  branch + `latest` release. The signing keystore is in the repo (`android/app/amplify.keystore`,
  password `amplify-personal`), deliberately, so updates install over each other.
- Media3 1.8.0, compileSdk/targetSdk 36, minSdk 24, Java; Guava is available transitively.

  ```
  { v:1,
    tracks: { <localId>: {title, artist, album, genre, dur, uri, art:'local:<artKey>'|''} },  // only tracks with srcUri
  ```
